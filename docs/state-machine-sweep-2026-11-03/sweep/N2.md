## N2-1 · Crash-report upload debounce (the crash ring's send-to-server clock)
- Area: client
- Verdict: needs-thought
- Why: once the 16-entry ring is full, a dedupe on the ring's LENGTH stops every later crash in that page from ever being uploaded.
- Key files: src/debug/crashTrap.js:53-58, src/debug/crashTrap.js:96-103, src/debug/crashTrap.js:129-145, server/src/feedback.js:78-104
- Entity: the page's crash telemetry (module-level, one per tab)
- State lives in: `_flushTimer` (crashTrap.js:44), `_flushAt` (crashTrap.js:45), `_lastSentLen` (crashTrap.js:46), the ring in localStorage `bt-crashlog` (crashTrap.js:19, capped at 16 at :137)
- States: idle, scheduled-slow (30 s, crashTrap.js:98), scheduled-fast (1.5 s for _IMMEDIATE kinds, :34/:98), sent (length remembered), quiet-entry (in the ring, no send: _QUIET :43)
- Transitions:
  - recordCrash(kind) of a non-quiet kind: idle → scheduled (crashTrap.js:144 → :96-102)
  - a faster kind while a slow send is pending: scheduled-slow → scheduled-fast (clears and re-arms, crashTrap.js:100-101)
  - timer fires: scheduled → sent (crashTrap.js:53-94), or → idle with nothing sent when `log.length === _lastSentLen` (:57)
  - boot with a non-empty ring: idle → scheduled-fast ('prior', crashTrap.js:269)
  - quiet kinds ('resume','died','evicted','touch-stale','audio-kick'): ring grows, no state change (crashTrap.js:43, :144)
- Guards that read it: `log.length === _lastSentLen` (crashTrap.js:57); server rate limit 12/h per sid (feedback.js:81-86)
- Counterpart/linked: server Feedback DO crashReport (feedback.js:78); BroTown watchdog markAlive (N2-2); QA reads the ring (tools/qa/mp/mp-killedpage.mjs:21, mp-rebuildjog.mjs:395) but every one clears it first (mp-killedpage.mjs:77, mp-bareground.mjs:78)
- Concerns:
  - [stuck] (high) The ring is capped at 16 (crashTrap.js:137) and persists across page loads, and quiet entries ('resume' on every tab switch, 'died' on every death) fill it without sending. Once full, its length is 16 forever. At boot the 'prior' flush sends it and sets `_lastSentLen = 16` (:58, :269); every later flush in that page compares 16 === 16 and returns (:57). So a CONTEXT_LOST, pixi-render-err, gl-rebuild or JS error in a regular player's session never reaches /api/feedback/crash until the NEXT page load on the same browser (and never if the player does not come back). The comment promises "every serious entry also uploads the whole ring buffer" (:26-27). Dedupe by the newest entry's `t` (or a counter) instead of the length. Evidence: crashTrap.js:57-58, :137, :269. Docs: none found (grep of docs/ for the dedupe: nothing; the QA scenarios all start from an emptied ring, so none can see it).
  - [race] (low) `_doFlush` reads the ring at fire time, so two tabs of one origin share one ring and each uploads the other's entries under its own sid (crashTrap.js:56, :60). Telemetry noise only. Docs: none found.
  - [persistence] (low) the stored ring has no shape number (crashTrap.js:134); readers tolerate it (feedback.js:93-97 clamps every field). Docs: none found.
- Making it explicit: keep `{lastSentT}` instead of a length and make the flush a two-state (idle/armed) object; small change.

## N2-2 · Page alive mark and killed-page detection (bt-alive + BroadcastChannel ping/pong)
- Area: client
- Verdict: watch
- Why: a single shared localStorage key carries every tab's mark, so with two tabs open a death is usually overwritten before the next page can see it.
- Key files: src/debug/crashTrap.js:162-222, src/debug/crashTrap.js:240-254, src/ui/BroTown.jsx:8785-8791
- Entity: the page (its _SID) as seen by the next page on the same origin
- State lives in: localStorage `bt-alive` {sid,t,vis,zone,x,y,hp,mb,up,rb,snd} (crashTrap.js:184), `_aliveAt` throttle (crashTrap.js:164), BroadcastChannel `_aliveChan` (crashTrap.js:165-174)
- States: no mark, alive-visible, alive-hidden, orphaned (page died open), reported (killed/evicted)
- Transitions:
  - watchdog tick, ≥5 s since last: → alive-visible/hidden (markAlive, crashTrap.js:175-186; caller BroTown.jsx:8791)
  - visibilitychange: alive-visible ↔ alive-hidden, own mark only (crashTrap.js:249-253)
  - pagehide: own mark → no mark (crashTrap.js:248)
  - next boot sees a foreign mark < 15 min old: ping; no pong in 700 ms → recordCrash('killed' | 'evicted') and the mark removed if still that sid (crashTrap.js:197-222)
  - another live tab answers the ping: mark left alone (crashTrap.js:218, :246)
- Guards that read it: `last.sid === _SID` and the 15-min window (crashTrap.js:200); `a.sid === last.sid` before removal (crashTrap.js:212)
- Counterpart/linked: N2-1 (the report rides the ring); tools/qa/mp/mp-killedpage.mjs
- Concerns:
  - [divergence] (medium) One key for every tab: with tabs A and B open, B's markAlive overwrites A's mark every 5 s (crashTrap.js:184), so when iOS kills A, the key usually holds B's live mark and the next page pings B, gets a pong, and reports nothing. Two tabs share one identity by design (CLAUDE.md), and the owner's black screens were reproduced with two iPhone windows (crashTrap.js:307). Evidence: crashTrap.js:166-169 (assumes the mark is the last page's), :184. Docs: crashTrap.js comment only.
  - [race] (low) iOS fires pagehide for a page going into the back-forward cache too; the mark is removed (crashTrap.js:248) and only returns on the next 5-s watchdog mark, so a kill in that gap goes unreported. Docs: none found (crashTrap.js comments only).
- Making it explicit: key the mark per sid (`bt-alive:<sid>`, swept at boot) so each page's lifecycle is its own; small.
