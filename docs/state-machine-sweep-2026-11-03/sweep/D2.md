## D2-1 · The AudioContext's life and the once-a-second audio watchdog
- Area: client
- Verdict: needs-thought
- Why: one context lives through null, running, suspended, interrupted, detached and closed. Seven writers drive it (unlock, play, fadeIn, the watchdog, resumeFromBackground, reclaimIfNeeded, _rebuildContext). Fifteen fields carry the state, and the reset list in _rebuildContext is hand-kept: it already misses several fields (see D2-6, D2-10, D2-11).
- Key files: src/data/gameDisplay.js:2176, src/data/gameDisplay.js:2136, src/data/gameDisplay.js:1857, src/data/gameDisplay.js:5508, src/ui/GameApp.jsx:243

- State lives in: `ctx` + `ctx.state` (gameDisplay.js:1756), `_master/_musicBus/_sfxBus` (1763-1780), `_unlocked` (5437), `_fadeUntil` (1882, 2272), `_analyser/_analyserBuf` (1922-1932), `_analyserProven` (1959), `_silentTicks` (2241), `_asleepTicks` (2194), `_watchdogTimer` (2258), `_suspendLogged` (5857)
- States: no-context, suspended or interrupted (asleep), running-healthy, running-silent (route detached), fading-in, closed, rebuilding
- Transitions:
  - first gesture (GameApp unlock): no-context → suspended or running; plus fadeIn and the watchdog starting (gameDisplay.js:5426-5466, GameApp.jsx:152-155)
  - any play() while not running: asleep → wake attempt plus fadeIn(0.6) (5849-5858)
  - watchdog tick, state 'closed': closed → rebuilding → new context (2179)
  - watchdog tick, 30 straight asleep ticks while visible: asleep → rebuilding (2194-2195)
  - watchdog tick, 3 ticks of provable silence: running-silent → global music torn down and restarted, zone track restarted (2240-2250)
  - visibilitychange or pageshow (hard): any → wake, then fadeIn if it was asleep, then _rebuildSources once running (5526-5560, GameApp.jsx:207, 345)
  - reclaimIfNeeded in a gesture: running-detached → rebuilding (2132, D2-2)
  - fadeIn and _ensureAudible: master gain → ramping, until _fadeUntil (1875-1883, 2262-2273)
- Guards that read it: _ctxLive (1839); _wakeCtx (1845); _whenRunning (1859); _audioHealthCheck's early returns: muted, hidden, gate closed (2177-2200); _masterIsSilent's fade and proof guards (1949, 1963); gestureKick (2094); GameApp onGesture's `state !== 'running'` (GameApp.jsx:257)
- Counterpart/linked: D2-2 (session reclaim), D2-3 and D2-4 (what the watchdog restarts), D2-6 (the deck's own tap), D2-8 (the gate silences the watchdog); src/ui/GameApp.jsx:186-361 holds every event that drives it; QA: tools/qa/audio-resume-check.mjs, tools/qa/mp/mp-comeback.mjs
- Concerns:
  - [race] (medium confidence) `_whenRunning` registers its listener on the context that is current then, but the callback re-checks `self.ctx`, which may be the NEW context (1861-1866). _rebuildContext closes the old context (2169), which fires 'statechange'. Every callback still parked on it then runs at once if the new context is running: a stale fadeIn, a stale `_rebuildSources` from resumeFromBackground (5559), and a stale startGlobalMusic play(buf) holding a buffer decoded on the dead context (4903). They are mostly saved by their own re-checks (url, source, deck token). The removeEventListener also goes to the wrong object (1863). Evidence: gameDisplay.js:1857-1867, 2169. Docs: none found.
  - [leak] (low confidence) every play() while the context is not running calls fadeIn(0.6) (5854). Each fadeIn parks one more 'statechange' listener through `_whenRunning` (1875). Footsteps, hits and peer sounds during an iOS interruption on a visible page pile them up, about 30 s' worth before the asleep rebuild drops the old context (2195). While hidden the watchdog never rebuilds (2182), so any sound a hidden page still asks for (socket-driven cues) keeps adding listeners. They all fire together on wake, each re-ramping the master. Evidence: gameDisplay.js:5849-5854, 1871-1885, 2182. Docs: none found.
  - [persistence] (low confidence) `_analyserProven` is set once (1959) and never cleared, not even by _rebuildContext (2136-2168), which builds a new analyser. After a rebuild, a new tap that WebKit never pulls (the v2.3.1602 case, 1924-1931) is "proven" from the old context's evidence. Its prefilled 128s then read as provable silence, so the silence branch tears music down every ~3 s (2240-2250). Evidence: gameDisplay.js:1959, 1963, 2142-2143. Docs: the v2.3.1602 note at gameDisplay.js:1924.
  - [opacity] (high confidence) the reset list in `_rebuildContext` (2137-2168) is the only statement of what the machine holds. It already leaves `_danceWant` (5186), `_analyserProven`, `_tagLoads`/`_sampleTag`/`_sampleLoadP` (4255, 4284) and `_gateLoops` (4680) behind. Every new field must be added here by hand, and nothing checks it. Docs: none found.
- Making it explicit: one `AUDIO_PHASE` field ('none'|'asleep'|'live'|'silent'|'rebuilding') written by a single `_setPhase`, with `_rebuildContext` resetting a declared list of per-context fields (one object, `this._perCtx = {...}`) instead of 30 hand-written lines.

## D2-7 · A land's air (ZONE_AMBIENT loop) torn down and re-decoded on a same-zone restart
- Area: client
- Verdict: watch
- Why: the ambience loop's start and stop ride startZoneAmbient. Its "leave" branch deletes the decoded loop, and every forced restart of the SAME zone runs that branch. So a tab return, an unmute or a watchdog restart in three Wheel lands stops the birdsong, lava or wind, drops it, and fetches and decodes it again, while the music beside it carries on seamlessly.
- Key files: src/data/gameDisplay.js:2683, src/data/gameDisplay.js:5567, src/data/gameDisplay.js:5559, src/data/gameDisplay.js:1443, src/ui/GameApp.jsx:207

- Transitions:
  - startZoneAmbient(zone with ZONE_AMBIENT): none → loading → looping, if still in the zone when it lands (2694-2711)
  - startZoneAmbient(any other zone): looping → fading-out → freed (2683-2693)
  - landed after leaving: loading → freed (2708)
  - sound gate closes or opens: looping ↔ waiting-for-gate (4759-4773)

- Concerns:
  - [divergence] (medium confidence) a restart is treated as a leave. resumeFromBackground(true) runs _rebuildSources on every visibilitychange to visible and on every pageshow (GameApp.jsx:207, 345 → gameDisplay.js:5547-5559). _rebuildSources nulls `_currentZoneAmbient` and calls startZoneAmbient(z) for any zone with a ZONE_MUSIC entry (5567-5573).
