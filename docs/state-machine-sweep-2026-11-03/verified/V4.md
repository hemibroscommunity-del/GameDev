# V4 · The phone's game socket: connect, reconnect, stop and tear down
- Verdict: needs-thought
- Severity: medium (a player stuck or misled, nothing lost: after a "Try now" tap the full-world screen can come back over a world the bro is already in, or a false "This account connected from another window" banner appears and the safety nets stay off until the next reconnect; a drop at the end of the loading screen leaves a frozen world with no message)
- Who can trigger it: honest player. (1) Tap "Try now" on the "BroTown is full" screen while the automatic try is still connecting (the moment it reads "Looking for a spot…"), or tap it twice, as a seat frees. (2) Switch apps or tabs while a stop screen is up (another device, the wrong key, the wrong site, the account check). (3) Lose signal while the loading screen is finishing. The dead-closure ("zombie") road needs joinTown to throw (an error road).
- Summary: Each phone keeps one socket (a live line) to the server. Opening, retrying and closing it happens in a dozen places; only some close the old line first, and no handler checks its line is still current. A "Try now" tap on the "BroTown is full" screen while the automatic try connects leaves a stray line that can later knock the live one off. Also, a drop just before the loading screen lifts freezes the world without a message, and a tab return retries screens meant to stay stopped.
- Key files: src/networking/wsClient.js:481-517 (connect and onopen), src/networking/wsClient.js:4468-4660 (the close ladder), src/networking/wsClient.js:420-438 (room-full retry and Try now), src/networking/wsClient.js:4995-5057 (tab return), src/networking/serverReady.js:166-187 (the veil), src/networking/wsClient.js:6203-6222 (teardown)

## The machine
- Entity, and where its state lives: this tab's connection to the game room, one closure per connected run of BroTown's socket effect (setupWebSocket, wsClient.js:281; BroTown.jsx:3358-3382). Closure variables: `ws` (wsClient.js:340), `WS_URL` (324), `reconnectTimer` / `reconnectDelay` (341-342), the refusal holders `_rfPending` ... `_lgPending` (349-389), `_readyRejoinTimer` (458), `_connectAt` (4851), `_hiddenAt` / `_lastAliveAt` (4808-4809), `_comeBackArmed` (4956), `_aliveTimer` (4852). On the shared state object S (the same object for every closure, BroTown.jsx:1043): `_realtimeStatus` (19 writes, 14 values), `_netHold`, `channel` (6201, 6220), `_frozenByAdmin`, `_joinRejectedFatal`, `_characterReset`, `_keyFellBack`. Module state: serverReady.js `_state`, `_veil`, `_veilTimer` (61-136); RoomFullScreen.js `el`, `timer`, `nextAt`, `attempts` (35-38). DOM screens: room-full, linger, verify gate, origin, device/key, resume banner, connect veil.
- States:
  - Finding the room: the lobby fetch is in flight, no socket yet (wsClient.js:481-494).
  - Connecting: `ws` is CONNECTING (497).
  - Open, not joined: onopen ran, status 'connected', join sent; the worker still ignores everything but the join (512-517, 586; server index.js:5077, join.js:774).
  - Joined: state_sync seen; ready (has prog3) or not ready, which rejoins in 5 s (1536-1593, 459-480).
  - Dropped: an ordinary close; 'disconnected', world held, backoff timer armed (4657-4659, 4788-4794).
  - Waiting: 'full' (room-full screen, ~5 s loop), 'linger' (countdown), 'locked' (popup, one retry at ~62 s), 'verify' (Turnstile gate) (4564-4617).
  - Stopped: 'origin', 'device', 'key' screens; 'frozen'; 'rejected'; reset reload (4491-4560, 4619-4634).
  - Hung up with a banner: 'idle' (the worker's 4006 or idleLogout) and 'superseded' (another join took the id) (4640-4649, 6175-6199).
  - Torn down: the effect's cleanup (6203-6222).
  - Readiness, beside it: ready, not ready, lost; veil none / grace timer / shown (serverReady.js:61-187).
- Moves:
  - effect run (bootPhase null): no socket → Finding the room → Connecting (wsClient.js:6202, 481-497)
  - socket open: Connecting → Open, not joined (503-517)
  - state_sync: Open → Joined; not ready → a rejoin in 5 s (1565-1569, 459-480)
  - ordinary close: Connecting / Open / Joined → Dropped → backoff timer (x1.5, at most 10 s) → Connecting (4657-4659, 4788-4794)
  - refusal message, then its close: → Waiting or Stopped, by a fixed priority order (1380-1511, 4491-4634)
  - room-full timer: Waiting(full) → Connecting (424); **"Try now": the same, with no check of a socket already connecting** (428-437)
  - linger timer: Waiting(linger) → Connecting (395); **lockout: an untracked timer → scheduleReconnect** (4570); **Turnstile token → connect(), unguarded** (4758-4766); **the key door-ask → scheduleReconnect, unguarded** (4547-4556)
  - dead pipe (15 s silent, or 7 s with no answer to a settled action), a connect stuck 10 s, a long freeze with the socket open: → `_forceRejoin`: detach, close, Connecting (4873-4884, 4891-4920, 5041-5053)
  - tab return / pageshow / a freeze over 5 s: socket closed → Connecting at once; **also when CLOSING, without detaching it** (5036-5040); **for every status but idle and superseded** (5032; 5112-5122, 4867-4869)
  - 2 idle minutes: Joined → Hung up(idle) (4640-4644, 6175-6199); first touch → Connecting (4958-4994)
  - another join of this id: Joined → Hung up(superseded) (4646-4649; server join.js:758-770); **back to 'connected' only at the next onopen** (513)
  - **a stray socket's events** (no "is this still my socket?" check in onopen 512, onmessage 839-843, onclose 4468, onerror 4661): its close re-arms the reconnect, and the later connect() replaces `ws` without closing the live, joined socket (496-498)
  - **effect cleanup: → Torn down, but the socket is closed with its handlers on, and the listeners and timers stay**, so the dead closure can reconnect (6203-6222; 5112-5123; 458-480; 4570; 483-493)
  - readiness: ordinary drop → 'lost' → veil after 3 s; **skipped, and never re-armed, while the loading screen is up** (serverReady.js:166-187)
- Diagram edges:
  - `NoSocket --effect run--> Connecting`
  - `Connecting --open, then state_sync--> Joined`
  - `Joined --ordinary close--> Dropped`
  - `Dropped --backoff timer--> Connecting`
  - `Connecting --room_full + close 4009--> WaitingFull`
  - `WaitingFull --timer or Try now--> Connecting`
  - `WaitingFull --Try now while still connecting--> TwoSockets !!`
  - `TwoSockets --stray socket's close re-arms a reconnect--> SupersededWhileLive !!`
  - `SupersededWhileLive --nothing until the next open--> Joined !!` (missing edge)
  - `Joined --dead pipe or long freeze (old socket detached)--> Connecting`
  - `Joined --2 idle minutes (first touch reconnects)--> HungUpIdle`
  - `Stopped --tab return--> Connecting !!` (should stay Stopped)
  - `Dropped --loading screen lifts--> FrozenNoVeil !!`
  - `Any --effect cleanup (old socket still reconnects)--> TornDown !!`

## What needs further thought
- Should "Try now" do nothing while an automatic try is already connecting (simplest), or cancel that try and start fresh? And should every socket ignore its own events once a newer one has replaced it?
- When the tab comes back to a screen that promises not to retry by itself (another device, the wrong key, the wrong site, a frozen account, the account check), should it stay stopped, as the screens and their specs say, or is one quiet retry per return wanted (it would let in a device the owner has just approved without the "Try again" reload)?
- If the line drops while the loading screen is finishing, should the world come up under the "Reconnecting…" veil, or should the loading screen wait, and keep talking, until the line is back?
- Making it explicit: one `openSocket()` as the only way to make a socket: it detaches and closes the one before, and each handler starts with `if (sock !== ws) return`. One declared state, `conn = {phase, why}` (connecting, open, joined, waiting:full|linger|locked|verify, stopped:origin|device|key|frozen|rejected|reset, hungup:idle|superseded, torn-down), changed only by a `setConn()` that also derives `_realtimeStatus`, readiness and the veil, and clears the timers the old phase owned (reconnect, lockout, readiness). One `mayAutoReconnect(phase)` table read by onclose, `_resumeRecover`, reconnectNow and the strike hold. No new messages; the worker is unchanged.
- Quick fixes vs design work: small, local fixes: the per-socket check in the four handlers; Try now returns while `ws` is CONNECTING; the cleanup detaches before closing, removes its two listeners and clears `_readyRejoinTimer`; `_resumeRecover` detaches a CLOSING socket and skips the stop statuses; the lockout wait goes in `reconnectTimer`; the veil re-applies when the loading screen lifts. Needs a decision: which stops a return may retry (question 2); whether 'locked' veils the world like a drop; whether state_sync should also write 'connected' (so a stray 'superseded' cannot stick); the onopen-to-state_sync window, where only the shop asks again.
