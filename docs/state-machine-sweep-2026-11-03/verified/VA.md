# VA · Small concrete bugs across twelve little machines (bundle)
- Verdict: needs-thought
- Severity: medium (a pet fetch that never gives up and, for two of five personalities, a pet whose position goes NaN; a zone wipe that never draws; a mute lost on a flaky connection; a public feedback board anyone can stuff; the rest are low: lost crash telemetry, visual gaps)
- Who can trigger it: honest player for most (pet fetch, zone wipe, mute during a blip, mic left on, peer wobble, ride lock); modified phone / any script for the feedback board; owner-only knowledge for the chain item (needs RELAYER_KEY set)
- Summary: Twelve unrelated small faults. Four are felt in play: the pet's fetch clock is never given the time (its give-up and retry timers never fire, and a playful or curious pet gets a NaN position), the zone-change colour wipe is stored as a number but read as an object so it never shows, a mute tapped during a reconnect vanishes on rejoin, and a peer's wobble is not drawn. The feedback board trusts any typed id, so votes can be stuffed. The rest are minor.
- Key files: src/ui/BroTown.jsx:7103, src/game/stateCleanup.js:19, src/game/chatMute.js:105, server/src/feedback.js:107, src/debug/crashTrap.js:57, src/rendering/systems/effectsRenderer.js:13539

## Concerns, verified
- [CONFIRMED] U1-1: petFetchStep gets `now: now` where `var now` (BroTown.jsx:7854, inside the same gameLoop starting 4773) is hoisted and still undefined at 7103, so every timer is dead: GIVE_UP_MS and BACK_MS comparisons are `undefined > x` = false, `skip` entries get NaN expiry and never lapse (a pile skipped once is never retried), the look throttle `lookAt` becomes NaN so it looks every frame. Worse, 7133 and 7137 use `Math.sin(now / 300)` for 'playful' and 'curious' pets (2 of 5 personalities, gameSystems.js:2219): `S._petX += NaN` makes the pet's x NaN for good (entityRenderer.js:17044 accepts any number). Evidence: src/ui/BroTown.jsx:7103, 7133, 7137, 7854; src/game/petFetch.js:101-126, 166. How checked: read; no other `now` assignment between 4773 and 7854 (grep); other `var now` at 9703 is a different function. Docs: docs/specs/pet-fetch.md says the timers give up and return home. Fix: use `performance.now()` (or `Date.now()`) at 7103 and in 7133/7137, i.e. declare `var now = performance.now()` once at the top of the frame. Who: honest player with a pet (the NaN part only playful/curious); not proven live on a device (I did not run it), but the JS semantics are certain.
- [CONFIRMED] G5 _zoneWipe: every writer stores `Date.now()` (gameEvents.js:942, :1084; zoneTransitions.js:1177, :1298, :1373, :1566 ...) but the clearer reads `S._zoneWipe.ts` (stateCleanup.js:19, `undefined` so NaN > 800 false, never cleared) and the renderer reads `w.ts`/`w.duration` (effectsRenderer.js:6731-6741, age NaN so `age < 1` false, never drawn). The flag stays truthy forever; no other reader exists (grep). Effect: no colour wipe on any zone change; harmless otherwise. Fix: make the writers store `{ ts: Date.now(), toZone }` (or have the two readers treat a number as ts). Who: every honest player on every zone change.
- [CONFIRMED] G5 chat mute during reconnect: setMuted writes `bt_muted`, checks only chatMuteSettled (caps + S.channel, both survive a drop; chatMute.js:92-112), channelShim.send returns silently when the socket is not OPEN unless the type is node_strike (wsClient.js:5522-5532); the next join's list replaces local (chatMute.js:171 `_write(ids)`). Nothing re-sends local-only changes after migration. The card says "Muted". Who: honest player muting a harasser during a network blip or deploy. Fix: remember mutes/unmutes sent while not OPEN (a small pending list) and re-send after the join, or refuse and say "reconnecting" in setMuted. Low-confidence sibling (more than 25 legacy mutes lost at migration) not checked further.
- [CONFIRMED] N2-1: once the ring holds 16 entries, `recordCrash` pushes then shifts so length stays 16; `_doFlush` returns early when `log.length === _lastSentLen` (crashTrap.js:57). After the first upload at 16 every later crash in that page life is skipped. Quiet entries ('resume', 'died'...) fill the ring fast, and boot 'prior' sends at the current length (:269). Reload resets `_lastSentLen` to -1 (:46), so it is per page life only. Who: honest player with a long, noisy session; effect is lost telemetry only. Fix: compare the newest entry (t+kind) instead of the length.
- [CONFIRMED] N2-2: `bt-alive` is one key for the origin (crashTrap.js:184); two tabs overwrite each other's mark, and the check only looks at the last writer (:197-200). A tab killed while another is alive is not reported; the design comment (:165-169) accepts this to avoid false deaths. Telemetry only. Fix, if wanted: key the mark by sid (`bt-alive:<sid>`) and scan all; otherwise leave.
- [CONFIRMED] M4-2: ChatBubble is always mounted (GameApp.jsx:738; it just returns null when closed, ChatBubble.jsx:~262), so the unmount-only abort (:187-189) never runs on close. The close effect clears the draft (:223) but a result arriving after that appends to the next draft (:293-303). Recogniser is non-continuous so it ends by itself after one utterance; the hot mic lasts seconds, not forever. Who: honest player closing the chat mid-dictation. Fix: in the `else` branch at :222 also `recRef.current?.abort()`.
- [CONFIRMED] R4-13 (peer wobble): the peer pre-filter (effectsRenderer.js:13539-13541) omits `_frozenUntil` and `_wobbleUntil`, though the draw's own guard includes them (:13067-13068). The wobble starts after the daze ends, so the daze term no longer keeps the filter open. Peers' frozen/wobble are recorded by applyElemHit on the peer record (gameEvents.js:3185). Also `clearElemStatuses` (elemHits.js:334) has no caller (grep whole src/tools/server tests); statuses are seconds long so the cost is a burn or chill showing a few seconds past a death or zone change on your own character. Visual only. Fix: add the two terms to the filter; call clearElemStatuses on death/respawn/zone change.
- [CONFIRMED] S8-19 / M4-11: `/api/feedback/*` is forwarded with no check (index.js:387-389) and submit/vote take `playerId` from the body (feedback.js:107, 149). Anyone can vote any number of times by varying the id, submit 5 tickets an hour per invented id, and grow `voters` without bound (storage writes). No docs defend it (TRAPS/handoff have no feedback entry). Who: modified phone or any script; an honest player cannot. Fix is NOT one line: needs a signed identity (device key or session token) or at least a per-IP limit via CF-Connecting-IP; decision for the owner (how much the board matters).
- [PLAUSIBLE] S5-16: rpcCall `fetch` has no timeout/AbortSignal (onchain.js:187-191) and jobs run in one room-wide promise chain (chainscore.js:164-168), so a hung RPC parks later checkpoints (a stuck job also holds that player's lane). Unproven link: whether the feature is live. wrangler.toml sets SCORES_CONTRACT on mainnet (line 73), and `_chainScoreConfigured` also needs the secret RELAYER_KEY, which I cannot see; if the owner set it, it is live. Impact is bounded: only checkpoints at milestone levels wait (a missed one is retried at the next level-up), game combat is not blocked (fire-and-forget, no input gate held across the fetch). Fix: add `signal: AbortSignal.timeout(8000)` to the fetch.
- [PLAUSIBLE] U1-7: `_lastStatsUpdateSig` is stamped before `S.channel.send` (BroTown.jsx:3451-3452) and the shim drops sends when not OPEN (wsClient.js:5522-5532), so a change made in a reconnect gap is marked sent. Unproven link: whether a gap-time change survives anyway (the rejoin's state_sync/player_state overwrites S.rpg and the worker holds equipment itself; the derived build is recomputed on adopt and its sig then differs, which re-sends). Low. Fix: stamp only after a send that was not dropped (have the shim return false when dropped).
- [CONFIRMED] P3-8: rideButtonView returns null while `S.lockedTarget` is a monster or the shield is up (RideButton.jsx:53-54), even when riding; rideCheck's `fighting` (BroTown.jsx:5326) lists shield/auto-attack/swing/bash/roll but NOT a locked target, so a rider with a locked monster (and no shield) has no button and is not stepped off. Escapes: clear the lock, leave the safe ground (auto step-off), or desktop key. Low. Fix: `if (!isRiding(S) && (...)) return null` for the lock/shield part of the hide rule.
- [PLAUSIBLE] P3-19: the scrim's `onPointerDown` closes the card (LoginScreen.jsx:316-320) so on touch the click that follows can land on Continue or Create beneath. Unproven link: browser click retargeting after the pointerdown target is removed (iOS usually delivers it to the element now under the finger). Harm is small: Continue opens the picker or Create reopens the same card. Fix: use `onClick` on the scrim (and swallowTapClick if wanted).
- [PLAUSIBLE] S3-1: structurally true. The tick wrapper (tick.js:233-236) only `finally`s; `_tickParties` (:435), `_tickPlayerRegen` (:446), `_flushPendingPlayerStates` (:453), `_tickPingAndAfk` (:462) and the whole broadcast section after :470 are outside `guard`. setInterval keeps firing but each tick aborts at the throw, so no broadcast and no AFK sweep: a silent room. Unproven link: no present throw source found in those functions (party.js:618, index.js:3635, persistence.js:579 read clean). Latent. Fix: wrap those four calls in `guard('parties' ...)` etc., and the broadcast section in its own try.

## What needs further thought
- Feedback board: does the owner want it to be a trustworthy ranking? If yes it needs a real identity on the request (the phone already has a device key for logins); if it is only a suggestion box, a per-IP limit and a cap on stored voters is enough.
- Pet fetch: confirm on a real phone what a playful/curious pet does today (I traced NaN from the code, did not run it). The fix is trivial either way and worth doing first.
- Mute and stats_update: should the channel report "not sent" to callers so every sender can decide to retry, rather than each stamping optimistically?
- Making it explicit: one rule for all of these: a "send" that can be dropped returns false, and any stamp, "Muted" card or signature is written only after a true. A `now` for the frame is declared once at the top of the game loop. A wipe is a small object `{ts, duration, toZone}` made by one helper `startZoneWipe(S, toZone)`, not typed in sixteen places.
- Quick fixes vs design work: one-liners: U1-1, _zoneWipe (helper or reader tolerance), N2-1, M4-2, R4-13 filter, P3-8, P3-19, S5-16 timeout, S3-1 guards. Small design: chat mute re-send, U1-7 shim return value. Needs a decision: S8-19/M4-11 identity on the feedback endpoints; N2-2 (probably leave).
