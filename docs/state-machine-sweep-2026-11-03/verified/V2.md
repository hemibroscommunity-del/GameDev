# V2 · A player's death and respawn, end to end (the worker's five dying seconds, the owed respawn, the phone's death screen)
- Verdict: needs-thought
- Severity: medium (items lost: a bag a dungeon death or a lost duel promised to keep is wiped with no pile when the game is closed during the 5 dying seconds and opened again fresh; also a second "YOU DIED" on the next launch, and up to 20 s frozen on the death screen after a rejoin)
- Who can trigger it: honest player: die (worst: in a dungeon, or losing a duel), close the tab or swipe the app away within 5 seconds, open the game again later. A milder road: die, switch away for more than 5 s, come back. Also deploy/restart timing (a restart inside the 5 s, then a reload).
- Summary: When you die, the server keeps you "dying" for 5 seconds, then stands you up in town and tells your phone. Those 5 seconds live only in memory. Close the game inside them and the server forgets; your save says 0 health, so the next launch kills you again, and that second death empties a bag a dungeon or duel had promised to keep, with no pile to pick up. The code meant to replay a missed "you're alive" never runs; a 20-second phone timer is the only rescue.
- Key files: server/src/index.js:3383, server/src/index.js:3527, server/src/join.js:876, server/src/join.js:1876, src/ui/BroTown.jsx:4902, src/ui/BroTown.jsx:5011

## The machine
- Entity, and where its state lives: one player. On the worker, in memory only: `ps.dying`, `ps.dead`, `ps.respawnAt` (server/src/index.js:3388-3391), `ps._deathKeepsBag` (index.js:3490), `ps._deathShield` (index.js:3443), `ps._respawnOwed` (index.js:3596, 3606). Saved: only `hp` (server/src/persistence.js:285); no phase, no keep-the-bag flag. On the phone: `S._dying`, `S._deathStart` (src/networking/wsClient.js:3149, 3159), `S.respawnTimer` (src/game/respawn.js:83), `S.rpg.hp` from the wire (wsClient.js:3115-3116), cached in localStorage `bt_rpg` (src/game/rpgSave.js:39-49, respawn.js:108).
- States:
  - Alive: hp > 0, not dying.
  - Dying (worker): dying + dead, respawnAt = death + 5 s; the bag already wiped, or kept for a dungeon or duel (index.js:3388-3491).
  - Respawned (worker): full bars, zone 'town', the next way into the Wheel judged from its arrival (index.js:3532-3541, server/src/movement.js:185-194).
  - Owed (worker): respawned with no socket or a send that threw (index.js:3596, 3606). A dead end (concern 1).
  - Zero on file: the record says hp 0 with nothing dying (a close or restart inside the 5 s); swept into a second death (index.js:3527-3528).
  - Dying (phone): `S._dying`, input frozen (BroTown.jsx:5018), death card.
  - Invulnerable (phone): 3 s after standing up (respawn.js:83).
- Moves:
  - a blow takes hp to 0: Alive -> Dying (server/src/hits.js:305, combat.js:2604, pvpextras.js:587 -> index.js:3383)
  - tick, hp <= 0 and not dying: Alive -> Dying, cause 'stuck-at-zero' (index.js:3527-3528)
  - tick, now >= respawnAt: Dying -> Respawned, player_respawned then player_state (index.js:3531-3608)
  - respawn with no socket, or the send threw: Respawned -> Owed (index.js:3596, 3606)
  - socket closes while dying: Dying -> state deleted, never lingered (server/src/linger.js:73, index.js:6396-6397). WRONG: the phase is lost, the record says hp 0
  - join: always a NEW object, dying false, respawnAt 0 (join.js:876-881, 1337-1338); the owed flag read off the new object (join.js:1876-1885). MISSING: never true
  - phone, player_died: Alive -> Dying, skipped when already dying (wsClient.js:3148-3149)
  - phone, player_respawned: Dying -> Invulnerable through applyLocalRespawn (wsClient.js:3242, respawn.js:37-110)
  - phone, watchdog: dying over 20 s and the wire says hp > 0 -> applyLocalRespawn 'town' (BroTown.jsx:5011-5014)
  - phone, catch-all: no server monsters, hp <= 0, not dying -> its own death and its own 3.5 s stand-up at TOWN_SPAWN (BroTown.jsx:4902-4958). WRONG: a second copy
  - phone, old local deaths: gameEvents.js:3685-3740 (5 s, 24*TILE), monsterCombat.js:1126-1278 (3.5 s, TOWN_SPAWN). WRONG: copies

  - `Phone Alive --player_died--> Phone Dying`
  - `Phone Dying --player_respawned--> Phone Invulnerable`

## Concerns, verified
- [CONFIRMED] S2-2 (the same as S1-2 [divergence]): the rejoin's replay of a respawn the phone never heard can never fire. Evidence: the flag is set on the old object (server/src/index.js:3596, 3606); every join builds a new one from defaults plus an allowlist that cannot carry it (server/src/join.js:876-881, 389-460) and reads the flag off the new one (join.js:1876-1885); the old object is dropped by the close (index.js:6396-6397), the linger's end (linger.js:134) or a resume (linger.js:177). How checked: grepped every reader and writer of `_respawnOwed` across the repo (4 lines) and every path that drops the old object; the suite pins only that the flag is set (server/test/combat-lifecycle.test.mjs:1203-1242). Impact is low. The phone's watchdog stands you up once 20 s have passed since the death and a rejoin's full player_state says hp > 0 (src/ui/BroTown.jsx:5011-5014; join.js:862, 1853). The commonest road to a frozen screen, a respawn sent into a suspended socket the worker still thinks is open, never sets the flag at all (index.js:3597-3601). If it did fire, it would carry the rebuilt object's zone, which is the phone's own claim (join.js:1882), not 'town'. Docs: the v2.3.1822 comments call this replay "the real fix" (src/game/respawn.js:15-17, BroTown.jsx:4999-5002).
- [PLAUSIBLE] S2-2 (extension): a rejoin after an unheard respawn puts the full-health body back where you died, while the phone still shows the corpse with input frozen. Evidence: the phone's join names its death spot (src/networking/wsClient.js:643-647). After a respawn the next way into the Wheel is judged from its arrival with a sprint allowance for all the time away (movement.js:185-194; server/src/lastplace.js:184-215), and a spot within it is taken as named. The phone stays frozen until 20 s after the death (BroTown.jsx:5011, 5018), and no message tells it it is alive. How checked: traced the join's place judge with what the respawn leaves behind. Unproven link: that the monster that killed you is still in reach when the body comes back (a death in the first stretches, back within 6-19 s). Docs: none.

## What needs further thought
- If you close the game during the 5 seconds after dying, should that count as "the death already happened"? Today the next launch kills you again, which empties a bag a dungeon or duel kept and shows a second death. The other choice: a save at 0 health comes back already stood up in BroTown, full health, nothing taken twice.
- Should "keep your bag" in a dungeon or a duel survive a closed app? If yes, the promise has to be saved with the character. Today it lives only in memory, a trade-off chosen for duels in v2.3.1616, before dungeons used it.
- The phone has four "stand back up" routines. Should the three left over from single-player go, now that every monster in the world is the server's?
- Making it explicit: one worker field `ps.life` = { phase: 'alive' | 'dying', until, keepsBag }, saved with the record, so that a close mid-death comes back as the same death with its time left, or straight to respawned. One function `lifeTo(ps, phase, why)` that every death, respawn and join calls. The phase is sent on player_state (`life`, behind a cap), so a phone follows it on every join instead of waiting for one message. On the phone, one `S.life` set only from the wire (the death screen on 'dying'; applyLocalRespawn on 'alive' after 'dying'), with the 20 s watchdog kept as the floor and the three old copies deleted.
- Quick fixes vs design work:
  - Quick:
    - delete the dead replay, or keep the debt in the last-place Map (lastplace.js:121) and send 'town', with the missing join test;
    - route the catch-all through applyLocalRespawn and drop its gold cut;
    - treat a cached hp of 0 as full at the warm start (BroTown.jsx:12103), which ends the fresh-page "YOU DIED".
  - Design (the owner's call):
    - what a close during the dying window means (the S1-2 [persistence] line; a small change once decided);
    - saving the keep-the-bag promise;
    - telling a rejoining phone that it is alive and where (the S2-2 extension).
