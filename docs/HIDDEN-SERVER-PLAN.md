# What the server keeps hidden, and the anti-bot plan (v2.3.3722)

The owner, 2026-10-28:

- *"I'm thinking about just leaving my game open source."*
- *"I'm wondering what else can I make 'hidden' since somebody just cloning my
  game is a concern?"*
- Then: *"The art was generated by chatGPT. The music was generated by Suno
  (paid version). The name ... has never been licensed. I'm fine with leaving
  all the art assets. It's very doubtful anybody would find them useful. Just
  hiding what you can in the server code (like anti bot, tuning, maybe other
  things that would be valuable to a copier) seems like the only necessary
  step."*

**Nothing here is built yet.** It is one lane after the showing (the order is at
the end). The repository stays public, art and music included.

## What can be hidden, and what cannot

**What cannot be hidden.** Anything a player's browser receives can be saved
by anyone who plays:

- the client's code;
- every picture and sound;
- every number the game shows: item stats, prices, the XP a level needs, the
  monster codex's roll ranges ("2-21 Iron Great Sword"), which the owner
  wanted players to see.

The tables the client mirrors from the server are in that list too
(`server/test/mirror-audit.test.mjs`: monster health and damage curves,
recipes and dishes, quest rewards, the progression formula, the gear tiers).
They stay public.

**What can be hidden.** Numbers only the server ever uses. The public code
keeps a placeholder for each, and the real value lives in the server's own
storage, set by the owner from the Test panel (the live flags' way: no
Cloudflare dashboard, no redeploy). The candidates:

1. **The anti-bot detector** (`server/src/botfp.js`, the `BOTFP` table):
   - every floor and threshold;
   - each signal's weight, and the score that flags;
   - the fleet (one device, many accounts) limits;
   - the signals still to come (below).

   A bot maker reading the code learns what is measured, not where the line is.
2. **The economic safety caps** (`HARVEST_HOUR_CAP` and the cook cap, the
   anti-bot review's hour caps): the rates past which the server quietly
   withholds a grant.
3. **Spawn and respawn timing, and population scaling**
   (`server/src/spawnscale.js`, the node respawn timer): server-only, and
   what makes a crowded zone feel right.
4. **Any new server-only number a copier would value.** It starts life as a
   hidden setting with a public placeholder.

**Honest limits:**

- **Today's values are already public.** They are in the repository's
  history, which has been public for months. Hiding protects the values from
  then on. Changing a value as it moves makes the public one stale.
- **Statistics can rebuild some values.** A determined copier can measure
  respawn times or caps by playing. Hiding raises the cost; it does not make it
  impossible.
- **The server code itself stays public.** What a copier needs most is the
  server, which holds combat, the economy, saves and the world. Keeping it
  public is the owner's choice for now. If cloning becomes a real problem, the
  next step is a private server repository with a self-hosted test runner, so
  tests don't cost paid Actions minutes.
- **The art and music are AI-made** (ChatGPT; Suno's paid plan). In the US,
  work made by AI without enough human authorship generally can't be
  copyrighted, so a licence on them would have been weak anyway. The name
  "BroTown" is unregistered; registering it as a trademark stays an option.
  This is not legal advice.

## How the hidden settings would work

- **One stored record** in the room's storage (a new key in ARCHITECTURE-HANDOFF's
  rule-2 registry). It is read when the room starts and merged over the code's
  placeholders.
- **Edited from the Test panel** behind the admin key, the way `devtools.js` and
  `liveops.js` already work. A change takes effect live and is never sent to a
  phone.
- **Tests run on the public placeholders.** A suite checks that a stored
  value overrides its placeholder, that a missing or broken one falls back to
  it, and that no hidden value ever appears in any message a phone receives.
- **A kill switch** (lower case, `liveops.test` §8) puts every value back to its
  placeholder.

## The anti-bot plan (from the same conversation)

Today's detector looks only at gathering gestures, and the phone computes the
numbers it judges, so a script can send human-looking ones
(`docs/specs/antibot-review.md`). The plan:

1. **Measured on the server, from what a bot must send anyway.** No new
   messages:
   - when each move, swing and dodge arrives;
   - path shapes: perfectly straight lines, repeated routes, instant turns;
   - the reaction time to a monster's wind-up (people spread out; scripts are
     too quick or too even);
   - clicks on the same spot;
   - session rhythm: no breaks, the same loop for hours.

   Each player's evidence is kept as a small running score (botfp.js's
   `botstat:` way), and the raw events are thrown away.
2. **Raw gesture points in the harvest message the phone already sends**,
   about 100 points and a few hundred bytes, in place of today's summary. The
   server computes the measures itself. That makes the messages bigger, not
   more numerous: Cloudflare bills incoming messages by count.
3. **The computer's E key.** Holding E harvests with no gesture and sends no
   fingerprint (`ExtractionSwipeLayer.jsx`, v2.3.3407). The fix:
   - harvest by dragging the gesture with the mouse for the full grade;
   - keep E as a slower, lesser harvest, and measure its key rhythm.

   Not before the showing: judges will use E.
4. **The network a player connects from.** Each connection tells the worker
   its network (`request.cf.asn` and `asOrganization`, on every plan). Play
   from a cloud server's network (Amazon, Google Cloud, Azure, Hetzner, OVH,
   DigitalOcean) is one more flag-only signal.
5. **A flagged player passes Turnstile again** (`verify.js`). A person passes
   without noticing; a script struggles. Still "flag, never act" (the owner,
   2026-07-03) in spirit: a check, not a punishment.
6. **Cloudflare's own tools, the owner's to switch on:**
   - **Bot Fight Mode** (free; test that it doesn't block real players' game
     connections first);
   - **a WAF custom rule** that challenges logins from cloud-server networks;
   - **one free rate-limiting rule** on new connections per address;
   - **paid tiers** (Super Bot Fight Mode; Enterprise Bot Management's bot
     scores) only if botting becomes a real problem.

## The order, after the showing

1. **The hidden settings**, with the anti-bot thresholds and the hour caps
   moved in first.
2. **Server-side fingerprints** for moving and fighting (1, 4, 5), every
   threshold hidden from the start, tested against the bot lab's scripts
   (`tools/qa/load/bot-lab.mjs`) and real play for false flags.
3. **The harvest's raw points and the computer's mouse harvest** (2, 3).
4. **Spawn timing and population scaling** moved into the hidden settings.
