# Card V4: one-case traps into rules (step 8.2, tag 5940 and on)

Card V2 left 63 traps of `docs/TRAPS.md` held for ONE case by a node suite
where a node test could hold the RULE (`docs/plan/status/V2.md`, "Left").
Card V4 holds each for the rule, in a guard under `tools/guards/` (a source
scan, a closed list, a table read, or the worker's own pure method run over
many inputs). No file under `server/test/`: no PR of this card deploys the
worker.

- One row a trap: its test, what the check holds, the break proof (the
  one-line change, tried by hand in a scratch copy on 2026-11-17, the FAIL it
  printed, then undone) and what was found stepped in today.
- Found: a place where the rule is already broken is a KNOWN entry in the
  guard's census (the count only falls) and is named here; nothing was
  fixed (the card changes no game or server code). The real faults are also
  under Found in `docs/plan/status/V4.md`.
- The old cell of each row stays in `docs/plan/census/traps.md` after
  "Before:".
