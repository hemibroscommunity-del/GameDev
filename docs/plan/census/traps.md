# The traps, read: one row for each heading of `docs/TRAPS.md` (card I, tag 5031)

Step 8.2 of `docs/GRAND-PLAN.md` wants each trap held by a guard with a break
proof. This page is that step's index, as a document: every heading of
`docs/TRAPS.md`, what would fail today if somebody stepped in it again, the
one-line change that should prove it, and whether a guard could hold it. A
later card (V, "traps into guards") starts from the rows that say `prose`
and `node`.

- Read on 2026-11-13 and 14, with `main` at commit `2d4138e`.
- **Nothing was run.** Every row is from reading the trap, the tests it
  names and the code. No guard was written and no break was tried.
- `docs/TRAPS.md` has 339 headings. Their numbers run from §1 to §341: there
  is no §54, §224 or §228, and one heading, at line 607, has no number (its
  row is "line 607"). §190 and §192 sit out of number order in the file; the
  rows keep the file's order.
- Eight readers took about 42 headings each, in two passes: the rows, then
  "the rule or one case" for every held row. A script then checked that
  every heading has a row, that every test a row names is in the repo and
  that every file a break names exists. About sixty of the named checks
  were looked up in their files by hand; all were there.

## How to read a row

- **§**: the trap's number in `docs/TRAPS.md`.
- **Title**: its heading, without the version stamp.
- **System**: provisional. One of: wire, server-core, combat, monsters,
  economy, skills, quests, social, identity, liveops, world, render, look,
  art, memory, page-thread, preload, audio, ui, input, desktop, qa, ci,
  docs; two with a slash when a trap sits between them. The system map is
  card B's, later.
- **Held today by**: the check that would fail if the trap were stepped in
  again, by name.
  - `node:` a suite in `server/test/` (run by `cd server && npm test` and by
    Server CI), or another test node runs, written with its path.
  - `phone:` a scenario of `tools/qa/mp/run.mjs` (a real worker and
    Chromium). CLAUDE.md §6 names the two that run on every PR (`questline`
    and `membudget`); the others run when somebody runs them.
  - `precheck:` a check of `tools/dev/precheck.mjs`, which a session runs
    before a push. No workflow runs it. A check that only warns
    (`proto-safety`, `shim-allowlist`) holds nothing.
  - `other:` a script, by its path. "run by hand only" in its note means no
    workflow, no precheck check and no `npm test` runs it.
  - **prose**: nothing would fail.
  - After the names, **(the rule)** or **(one case: ...)**. "The rule": the
    check would fail on a new stepping-in wherever the trap applies (it
    scans the source, or it is a door or registry test, or the trap is about
    one spot and the check pins that spot). "One case": the check pins only
    the instance the trap found, named after the colon; the same mistake in
    a new place turns nothing red.
  - A test that the trap names, and that exists, but does not check the
    trap's rule is not counted: the note says so. "unsure" in a note means
    the reader could not tell from reading whether the test would fail.
- **Break**: the one-line change that steps in the trap and should turn the
  holding test red. Each is marked "not run". For a prose row it is the
  change a future guard would have to catch, and ends "nothing red today".
  "none" means the trap is a habit of judgement with no line of code to
  name.
- **A guard could hold it**: `node` (a test node runs with no browser: a
  scan of source, a unit test, a check of files), `browser` (it needs the
  real page in Chromium) or `no`. It is the cheapest kind that could: a row
  that only a phone scenario holds today says `node` when a node test could
  hold it too, and a "one case" row gives the kind that could hold the
  whole rule.
- Tags are written as bare numbers ("tag 4674" is the change that deleted
  the old map's phone tests). Precheck's tag check reads a tag written in
  full as this change's own.
