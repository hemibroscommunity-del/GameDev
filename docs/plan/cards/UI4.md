## PURPOSE (the owner's own, 2026-11-27, with the zip)

*"This represents the consolidated design direction after 17 iterations of reviewing and redesigning BroTown's menus. Use the interactive prototype as a visual and behavioral reference, not as production code. Preserve existing gameplay functionality and server-authoritative mechanics. Start by implementing the shared UI components, adaptive layout system, Bro, Combat and Gear menus. Validate these within the actual game before implementing the remaining menus. Do not compromise readability, available screen space, gameplay visibility or device fairness to accommodate a design. Flag unresolved requirements rather than inventing solutions."*

And, 20 minutes later: *"Some things may be better designed as already in the game like probably the bag menu and character design but maybe not"*.

So after this card: every piece of a menu SAYS what it is (a fact, a thing to inspect, a way to go somewhere, a commitment) by a role its code names, and looks it (V17:37-49); Bro leads with the three weapons and what can be improved; a weapon's page leads with its upgrades; and the owner has, for each of the first-slice screens, the real game at the four reference sizes beside V17, measured, with every conflict listed for them. Where the game already does what V17 asks, or does it better, the game's is KEPT and both are shown: V17 is never taken blindly, and nothing is settled by invention.
